# Keel

AI 코딩 도구를 위한 지식 베이스와 훅.

[English](README.md)

Andrej Karpathy 의 LLM Wiki 아이디어를 바탕으로 만들었습니다 (https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f).

Claude Code / Codex 와 함께 쓰는 개인 지식 베이스(KB)를 로컬 웹 앱으로 설치합니다.
훅 설치, 지식 베이스 생성, GitHub/로컬 폴더 히스토리 색인, Obsidian 연결까지
전부 브라우저 화면에서 사용자가 직접 고릅니다.

- **훅** 은 Claude Code / Codex 가 일하는 도중 정해진 순간(세션 시작,
  답변 끝 등)에 자동으로 끼어드는 작은 스크립트입니다. 예: 세션이
  시작될 때 지식 베이스를 자동으로 읽어 두게 하는 것.
- **CLI** 는 터미널(명령어를 치는 검은 화면)에서 쓰는 프로그램을
  뜻합니다. 여기서는 `claude`, `codex`, `gh` 세 가지를 말합니다.

## Keel 받기

셋 중 하나를 고르세요. 어느 방법이든 마지막에는 같은 설치 화면이 브라우저에 열립니다.

1. **내려받기 (가장 쉬움).** [최신 릴리스](https://github.com/badjin/keel/releases/latest)에서
   `keel-<버전>.zip` 과 `INSTALL.md` 를 내려받아 새 폴더 하나에 함께 넣습니다.
   그 폴더에서 터미널을 열고 `claude`(또는 `codex`)를 실행한 뒤 `INSTALL.md 따라 해 줘` 라고 말합니다.
2. **클론.**
   ```
   git clone https://github.com/badjin/keel
   cd keel
   claude
   ```
   그다음 `INSTALL.md 따라 해 줘` 라고 말합니다.
3. **AI 에게 맡기기.** 비어 있는 새 폴더에서 `claude` 또는 `codex` 를 열고
   `https://github.com/badjin/keel 을 클론해서 INSTALL.md 를 따라 해 줘` 라고 말합니다.

## 요구 사항

- macOS
- `python3` 3.9 이상 (표준 라이브러리만 사용, 별도 설치 불필요)
- `git`
- (선택) `claude`, `codex` CLI, `gh` CLI, Obsidian — 없어도 나머지는 그대로 동작합니다

처음 여는 Mac이라면 아래 과정 중 `xcode-select --install` 창이 갑자기 뜰 수
있습니다. Apple의 개발자 도구를 설치하는 정상적인 절차이니, 뜨면 그냥
설치를 눌러 진행하고 끝난 뒤 다시 시도하면 됩니다.

## 빠른 시작

**AI 에이전트(Claude Code 또는 Codex)가 있다면 이 순서로 시작하세요:**

1. **터미널 앱을 엽니다.** (Spotlight 검색 — 화면 오른쪽 위 돋보기 —
   에서 `터미널` 을 입력하고 엔터)
2. **키트 폴더로 이동한 뒤, `claude` 또는 `codex` 를 대화형으로 엽니다.**
   (`cd ` 까지 입력한 뒤 압축 푼 키트 폴더를 파인더에서 끌어다 터미널 창에
   놓고 엔터. 한 번 실행되고 끝나는 `claude -p` / `codex exec` 대신
   대화형 세션을 쓰는 것입니다 — Codex 는 폴더를 처음 열 때 신뢰할지
   물어보는데, 그때는 허용하세요.)
3. 에이전트에게 **"`INSTALL.md` 읽고 따라 해 줘"** 라고 말합니다. 서버를
   켜는 명령을 실행해도 되는지 물으면 허용해 주세요. 에이전트가 서버만
   켜고, 이후 터미널에 뜨는 `Open / 열기:` 주소가 브라우저에서 열리면 브라우저
   페이지의 네 단계(훅 → 지식 베이스 → GitHub → 완료)를 사용자가 직접
   진행합니다. 에이전트가 켠 서버를 끄려면, 에이전트에게 꺼 달라고
   하거나 그 터미널 창을 닫으세요.

### AI 없이 직접 켜기

1. **터미널 앱을 엽니다.** (Spotlight 검색 — 화면 오른쪽 위 돋보기 —
   에서 `터미널` 을 입력하고 엔터)
2. **키트 폴더로 이동합니다.** 터미널에 `cd ` (cd 다음에 띄어쓰기 한 칸)
   까지만 입력한 뒤, 압축을 푼 키트 폴더를 파인더에서 끌어다 터미널 창에
   놓으면 경로가 자동으로 채워집니다. 그 상태에서 엔터를 누릅니다.
3. **서버를 켭니다.**

```
python3 app/server.py
```

터미널에 뜨는 `Open / 열기:` 주소를 브라우저에서 열면 설치 화면이 시작됩니다.

4. **다 쓴 뒤 서버를 끄려면**, 서버를 켠 터미널 창으로 돌아가
   `Control` 키와 `C` 키를 같이 누릅니다 (Ctrl+C). 창을 그냥 닫아도
   됩니다.

## 네 개의 탭

1. **훅** — Claude Code / Codex 에 심을 훅을 고릅니다 (지식 베이스 자동 로드, 추측
   답변 차단, 완료 전 검증 요구 등). 설치된 CLI만 표시됩니다.
2. **지식 베이스** — 지식 베이스를 어디에 만들지 정합니다. 빈 지식 베이스로
   시작하거나, 로컬 폴더들을 골라 색인을 만듭니다.
3. **GitHub (선택)** — GitHub 저장소나 로컬 git 저장소의 커밋 히스토리를
   기간별로 지식 베이스 페이지로 만듭니다. 원하면 LLM 요약도 붙입니다.
4. **완료 / Obsidian** — 설치 요약을 보여주고, Obsidian 이 있으면 지식 베이스를
   바로 열어 줍니다. 없으면 설치 안내를 보여줍니다.

## 개인정보

- GitHub 토큰은 서버가 켜져 있는 동안 메모리에만 있습니다. 디스크, 로그,
  `.git/config`, URL 어디에도 저장되지 않습니다.
- 커밋의 메타데이터(날짜·작성자·제목·건드린 파일 경로)만 읽고 기록합니다.
  파일 내용은 읽지 않습니다.
- LLM 요약 기능을 켜면, 커밋 제목이 선택한 CLI(`claude` 또는 `codex`)의
  제공자에게 전송됩니다.

## 지식 베이스 관리 — 가끔 린트 돌리기

지식 베이스를 쓰다 보면 고아 페이지(다른 페이지에서 링크가 안 걸린 페이지), 깨진 링크(가리키는
페이지가 없는 `[[링크]]`), 한쪽만 걸린 링크(A는 B를 가리키는데 B는 A를 가리키지 않는 경우)가
생깁니다. 이런 문제는 저절로 고쳐지지 않습니다.

가끔(한 묶음의 변경 뒤나 매주 정도) 어느 폴더에서든 Claude Code 나 Codex 에게
"지식 베이스 린트 돌려줘" (또는 "위키 린트 돌려줘") 라고 말해 주세요. `kb-lint` 스킬이 세 가지 문제를 찾아 보여주고 고칩니다. 훅 탭에서
스킬을 지울 때 **"스킬도 제거"** 체크박스를 켜면 `kb-lint` 도 함께 제거됩니다.

## 되돌리기 순서

**순서가 중요합니다.** 훅을 지우지 않은 채 `~/.keel` 폴더부터
지우면, 이미 등록된 훅들이 가리키는 스크립트가 사라져서 Claude Code /
Codex 가 오류를 내며 멈출 수 있습니다. 아래 순서를 지켜 주세요.

1. **먼저 훅을 지웁니다.** 서버를 다시 켜고(`python3 app/server.py`)
   화면에 보이는 CLI 체크박스(Claude Code, Codex 등)를 전부 켠 채로 둔
   뒤, 훅 탭의 **"키트 훅 모두 제거"** 버튼을 누릅니다. 체크박스를 끄면
   그 CLI 는 제거 대상에서 빠져 훅이 그대로 남을 수 있습니다. 설치했던
   지식 베이스 스킬도 함께 지우려면 **"스킬도 제거"** 체크박스를 켜세요.
   (버튼을 못 쓰는 상황이면, `~/.claude/settings.json` ·
   `~/.codex/hooks.json` 옆의 `.bak-before-kit` 파일은 설치 당시 그
   파일이 없었고 아직 센티널도 없었을 때만 키트가 만들어 두는
   것입니다 — 되돌리면 잠금 상태에서는 벗어나지만, 그 뒤에 그
   파일에 생긴 변경은 함께 사라집니다. 없다면, 같은
   자리의 `*.bak-*` 백업 중 `grep -c '/.keel/hooks/' <백업파일>`
   이 `0` 을 출력하는 가장 최근 것을 원래 이름으로 되돌리세요 — 그
   값이 `0` 이라는 것은 그 백업이 키트 설치 이전 상태라는 뜻입니다.
   `0` 이 아닌 백업을 되돌리면 이미 키트 훅이 들어있는 상태로
   복원되어, 그다음 `~/.keel` 을 지우면 위 경고의 오류가
   재현됩니다. `~/.codex/config.toml` 은 되돌릴 필요가 없습니다 —
   키트 훅 명령을 담고 있지 않아 잠금의 원인이 될 수 없고, `hooks =
   true` 는 아래 문단에서 다룹니다. `.bak-before-kit` 도 `*.bak-*` 도
   없는 설정 파일은 키트가 새로 만든 것이라 되돌릴 원본이 없습니다 —
   그때는 버튼을 쓰세요.)
2. **그다음에만** 키트가 만든 나머지 상태까지 전부 지웁니다:

```
rm -rf ~/.keel
```

이 명령은 지식 베이스 폴더 자체와 Obsidian 은 지우지 않습니다.

`~/.codex/config.toml` 의 `hooks = true` 줄은 이 절차로 지워지지
않습니다 — 이 키트가 설치하지 않은 다른 Codex 훅이 이 설정에 의존할 수
있기 때문입니다. 정말 필요 없다고 확신하면 직접 지우세요.

## 지식 베이스 자동 업데이트

`wiki-auto-update` 훅(기본 켜짐)은 세션이 끝날 때마다 판단해서 움직입니다.

- **건너뛰는 경우** — 세션이 짧거나(실제 사용자 발화 2개 미만 또는 전체 200자 미만)
  내용이 없으면 아무것도 하지 않습니다. 이번 세션에서 쓰던 CLI(`claude`/`codex`)가
  PATH 에 없어도 건너뜁니다.
- **자동으로 반영하는 경우** — 지금 작업한 위치가 git 저장소이거나, 대화 내용이 지식 베이스
  루트 `index.md` 에 이미 있는 주제와 맞으면 자동으로 지식 베이스를 갱신합니다.
- **직접 요청** — "위키 업데이트해 줘"(지식 베이스 업데이트해 줘), "이번 세션 내용을 위키에
  반영해 줘"(지식 베이스에 반영해 줘)처럼 명시적으로 요청하면 `kb-ingest` 스킬이 그 자리에서
  바로 처리합니다(이 훅과는 별개입니다).
- **쿼터를 씁니다** — 반영은 세션이 끝난 뒤 백그라운드에서 선택한 CLI를 한 번 더 실행해서
  이뤄지므로, 그 CLI의 사용량(쿼터)을 씁니다.
- **임시 파일** — 이번 세션의 대화 내용은 `~/.keel/state/auto-update/` 아래
  임시 작업 파일로 잠깐 저장되어 선택한 CLI에 전달되고, 처리가 끝나면(반영·건너뛰기·오류
  어느 경우든) 그 파일은 바로 삭제됩니다. 백그라운드 워커 프로세스가 도중에 강제 종료된
  경우에만 파일이 남을 수 있습니다.
- **백그라운드 실행의 읽기/쓰기 범위** — Codex 의 백그라운드 실행은 지식 베이스 밖의 파일도
  읽을 수 있습니다(쓰기는 자체 샌드박스 작업 폴더로 지식 베이스 안에 한정됩니다). Claude 의
  백그라운드 실행은 읽기·쓰기 모두 지식 베이스 안으로 한정됩니다.
- **끄는 방법** — 훅 탭에서 "세션이 끝나면 지식 베이스 자동 업데이트" 체크박스를 끄고 다시
  설치하세요.
- **로그** — `~/.keel/state/auto-update.log` 에서 건너뛴 이유와 처리 결과를
  확인할 수 있습니다.

## 제한

- macOS 전용입니다 (경로 규칙이 macOS 기준). Windows/Linux 는 지원하지
  않습니다.
